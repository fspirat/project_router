# Этап 2: сервер для приложения iPhone — отчёт

## Часть A. Коротко для владельца

**Что сделано.** Пока всё лежит только в репозитории. Ничего не выложено и не закоммичено. Роутер не трогали.

- **Вход в приложение.** Нужен пароль от панели. Потом бот присылает три числа и кнопку «Это не я». Нажимаешь число, которое показывает телефон.
  - После входа телефон получает свой ключ на 90 дней. Пока приложением пользуешься, срок продлевается, но не дольше года.
  - На сервере ключи хранятся только в зашифрованном виде (хэш).
- **Отзыв доступа телефона** есть в трёх местах:
  - в самом приложении;
  - в панели: раздел «Безопасность» → новый блок «Приложения на телефонах», кнопка «Отозвать»;
  - в боте: новая команда `/apps`.
- **«Выйти на всех устройствах»** в панели теперь сначала спрашивает подтверждение. Кроме сайта, она выключает приложение на всех телефонах и забывает запомненные браузеры: каждый браузер снова попросит код из Telegram.
- **Ограничения:**
  - 5 входов в час с одного адреса;
  - не больше 10 телефонов;
  - лимиты на частые действия;
  - между перезапусками VPN пауза 15 секунд для всех телефонов;
  - опасные действия (перезагрузка, смена сервера и т.п.) приложение переспрашивает.
- **Кнопка «Это не я»** или подбор пароля с разных адресов закрывают вход в приложение на час. В Telegram приходит тревога.
- **Журнал.** Каждое действие из приложения записывается. Важные действия бот присылает с подписью «Из приложения «имя телефона», IP …».
- **Выключатель.** Если на сервере есть файл `app_disabled`, приложение сразу перестаёт работать. Панель и бот работают как раньше.
- **Попутные исправления:**
  - смена ключа роутера (workflow «Rotate router token») больше не ломает бота;
  - бот при `/update` честно пишет, что VPN перезапустится на несколько секунд;
  - трафик за сутки считается по времени Самары (как на роутере), а не по UTC;
  - ссылка в сообщении «Новое устройство в сети» ведёт на вкладку «Устройства»;
  - найдена и исправлена старая ошибка: защита от подбора пароля (fail2ban для страницы входа) на деле никого не банила.

**Что проверено.**
- Автоматический тест на стенде без интернета: 439 проверок, по всем пунктам T1–T29 из плана.
- В одном прогоне из двух одна проверка на время не уложилась, потому что медленно ответила подставная копия роутера в тесте. При повторе всё зелёное, отдельно эта проверка проходит 3 раза из 3.
- Проверено на PHP 8.3. На сервере PHP 8.5, там код впервые запустится при выкладке, и сразу после неё автоматическая проверка (Verify) его проверит.

**Что изменится на сервере при выкладке** (нужно твоё «да»):
- Добавятся новые PHP-файлы (`app.php`, `app-lib.php`, `data-lib.php`), обновятся старые.
- В nginx добавится блок для `/router/app/v1/`, будут проверка `nginx -t` и перезагрузка nginx (`reload`). Если проверка не пройдёт, скрипт сам вернёт старый конфиг.
- Перезапустится fail2ban, в нём появится новое правило `fspirat-router-app`.
  - Правило для страницы входа теперь будет банить по-настоящему: 5 неверных паролей за 10 минут — бан на час.
  - Бан закрывает весь порт 443, а через него идёт и твой VPN-сервер NL. Значит, 5 ошибок с домашнего адреса оставят дом на час без своего NL. Подписка nosok при этом работает.
  - Нужен твой ответ: оставить бан на час или сделать короче.
- У бота появится команда `/apps`.
- Панель и бот работают как раньше.

**Как откатить:**
1. Быстрее всего — выключатель через Server ops: `touch /var/lib/fspirat-router-auth/app_disabled`. Включить обратно: `rm` того же файла.
2. Выкинуть все телефоны:
   - «Выйти на всех устройствах» в панели (выйдет и сам сайт);
   - или `/apps` в боте, по одному телефону;
   - или одна команда через ops (она есть в CLAUDE.md).
3. Вернуть nginx как было: копии `/etc/nginx/snippets/fspirat-router.conf.bak-auth-<время>`, затем `nginx -t` и `reload`.
4. Если бан задел дом: `fail2ban-client set fspirat-router-auth unbanip <IP>` (или `fspirat-router-app`).

### Отступления от `docs/ios/inventory.md`
1. `fsr_router_call()` возвращает третьим элементом исходный или починенный текст JSON. Чтения, действия и задачи отдают его как есть: при декодировании и обратном кодировании `{}` превратился бы в `[]` (`status.svc`). HTTP-код берётся из `stream_get_meta_data()['wrapper_data']`, а не из `$http_response_header`: тот устарел в PHP 8.5.
2. Починка JSON (сырые управляющие символы в строках, битый UTF-8) работает для любого ответа CGI, а не только для `/status`; её получают бот и все действия. Если ответ пустой или не чинится — `502 router_bad_reply`.
3. Для `op=apprevoke` из веба сообщение в Telegram шлёт `data.php`, с именем телефона и только если отзыв реально случился. `check.php` для `app*` молчит, чтобы не было второго сообщения. В `FSR_ACTIONS` флаг по-прежнему `true`.
4. Ключ в адресе при запросе из браузера: порядок из спецификации сохранён (сначала 403 `browser_request`), но настоящий ключ `fsr1_` всё равно отзывается (`url_leak`) и пишется строка `APP_URLTOKEN`.
5. Дополнения по ревью (внесены в спецификацию):
   - `Bearer` только с учётом регистра (§7.4);
   - вход по паролю атомарно: `fsr_attempt` в транзакции `BEGIN IMMEDIATE`, и для приложения, и для веба;
   - замок («Это не я», подбор) и «выйти на всех» закрывают ожидающие и одобренные входы;
   - вызовы, которые роутер точно не выполнил, в лимиты не идут (§7.8);
   - места для вызовов роутера: 2 одновременно, ожидание места до 4 с, потом `429 busy`;
   - «роутер молчит»: 30 с без вызовов;
   - общий срок запроса 25 с (`FSR_APP_BUDGET`);
   - в таблицу ошибок добавлен `429 busy`.
6. Изменения в вебе, которые видны пользователю:
   - logout-all спрашивает подтверждение, отзывает телефоны и забывает браузеры (вопрос §12 п.2 решён по рекомендации);
   - jail `fspirat-router-auth` теперь действительно банит;
   - ссылка `#dev`.
7. Граница суток трафика — по Самаре (вопрос §12 п.16, по рекомендации).
8. Verify делает больше, чем в §10.2:
   - `fail2ban-regex` на реальном fail2ban для FAIL, LOCKED и APP_BADTOKEN;
   - печатает `pm`/`pm.max_children`;
   - на время проверки ключа в адресе глушит тревогу (`touch app_urltoken_alert`, потом возвращает mtime);
   - `exit 1` при ❌.

### Риски и открытые пункты
- **PHP 8.5 не запускался.** Проверено только grep-ом, что нет синтаксиса и функций 8.4+; `php -l` чистый на 8.3.6. Первый настоящий запуск — на сервере, затем Verify.
- **nginx и fail2ban не запускались локально.** `nginx -t` не выполнялся; страховка — откат в `nginx-apply.py`. `fail2ban-regex` проверяется только в Verify.
- **Флейк T17.** «первые два → 200» получили `200 504`: один раз из двух полных прогонов (вторая заглушка роутера под нагрузкой не уложилась в 10 с). Отдельно T17 проходит 3 из 3. Тесты стоят в Checks у Deploy server, поэтому флейк остановит выкладку до любых изменений на сервере; лечится перезапуском. Стоит расширить запас по времени в тесте.
- **fail2ban и порт 443.** `fspirat-router-auth` впервые начнёт банить, а бан закрывает весь 443 вместе с Xray NL. Решение владельца 13.10.2026: bantime 15 минут для `fspirat-router-auth` и `fspirat-router-app`.
- **php-fpm.** `pm.max_children = 5` (проверено 13.10.2026), пул общий с check.php, входом и ботом. Приложение занимает не больше 3 воркеров, ждущих роутер. Отдельный пул в v1 не входит.
- **Не проверено до выкладки (§8.5), сделать через ops, только чтение:**
  - `request_terminate_timeout`/`max_execution_time` ≥ 120 с — для задач ping и speedtest;
  - `router.token` совпадает со сниппетом (`cmp`, без вывода);
  - есть `pdo_sqlite` в php-fpm;
  - realip.
- **Роутер:**
  - нет общего замка на перезапуски PassWall для веба, бота и приложения;
  - лимиты uhttpd и поведение `subscribe.lua` не проверены (§5 п.31);
  - дефекты CGI на сервере только обходятся, на роутере не исправлены (§12 п.9).
- **Вход зависит от Telegram.** Без бота — `503 tg_unavailable`.
- **Код-откат через Deploy server старого коммита** не удаляет `app.php` и блок nginx (старый `lib.php` → 500/502 JSON). Правильный откат: выключатель, при необходимости — копия `.bak-auth-*` сниппета.
- Остальные вопросы §12 открыты. Само приложение iOS — этапы 3–5.

### Порядок выкладки
0. С разрешения владельца — проверки §8.5 через Server ops, только чтение.
1. Коммит. `deploy-web.yml` срабатывает автоматически на push в `main` с `web/**`. Варианты:
   - запустить Deploy server по ветке (`workflow_dispatch`) и потом слить в `main`;
   - или сначала запушить без `web/`, потом с ним.

   Если веб уйдёт первым, это не страшно: блок скрыт, пока старый `data.php` не отдаёт `apps`.
2. **Deploy server** (`nginx: true`). Шаги внутри:
   - Checks: lint и 439 тестов;
   - Upload;
   - Install: php, `site.json`, фильтры, `systemctl restart fail2ban`;
   - nginx: `fsr-limits.conf` → `nginx-apply.py` этап 7 → `nginx -t` → reload;
   - бот: `router.token`, `setMyCommands` с `/apps`;
   - **Verify**.
3. Разобрать лог Verify. Все строки должны быть ✅:
   - `token_missing` 401;
   - `token_in_url` 400;
   - `browser_request` 403;
   - Bearer на `/router/api` → 401;
   - 429 в JSON;
   - jail `fspirat-router-app`;
   - 3 строки `fail2ban-regex`;
   - `nginx-apply.py` повторно — «уже настроен».

   При ❌: включить выключатель `app_disabled` и разбираться (веб при этом работает).
4. **deploy-web**: push `web/**` в `main` или ручной запуск.
