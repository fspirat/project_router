### 🟡 Medium

1. **CSRF держался на одном постоянном заголовке `X-FSR: 1`, действия шли через GET.**
   `server/auth/nginx-apply.py` (`CSRF`), `web/index.html` (`H = {'X-FSR': '1'}`), `router/www/cgi-bin/fspirat` (все action через GET).
   Риск: сейчас атака с чужого сайта не проходит (свой заголовок чужой сайт без CORS не поставит), но защита была одна,
   без проверки Origin и без привязки к сессии; любая будущая ошибка в CORS/прокси открыла бы перезагрузку роутера ссылкой.
   Сделано: CSRF-токен = HMAC от токена сессии (`fsr_csrf()` в `lib.php`), страница берёт его из `/router/data?csrf=1`
   и шлёт в `X-FSR`; `check.php` (auth_request) для **не-GET** запросов к `/router/api` и `/router/data` проверяет токен
   и `Origin: https://fspirat.online`, иначе 403. На роутере действия — **только POST** (GET → 405). Чтение (status, net, pingone) — GET.
   Почему так: токен не хранится отдельно и сам меняется с новой сессией; проверка — на сервере до роутера, поэтому
   на роутере ничего не надо знать о сессиях. Telegram-вход не тронут.
2. **Список сервисов мог указывать внутрь (SSRF).** `router/www/cgi-bin/fspirat` (settargets), `router/bin/fspirat-targets`.
   Риск: замер идёт с роутера — можно было «пинговать» `192.168.1.1`, `127.0.0.1` и домашнюю сеть
   (вслепую: виден только отклик, ответ не показывается; и только после входа).
   Сделано: при сохранении запрещены localhost, `.local/.lan/.internal`, имена без точки, IP 0/8, 10/8, 127/8, 100.64/10,
   169.254/16, 172.16/12, 192.168/16, 198.18/15, ≥224, записи вида `2130706433`, `0x7f000001`, `127.1`;
   при **каждом замере** имя ещё раз проверяется по DNS (защита от DNS rebinding); curl — только http/https, без редиректов.
   Логин в URL (`user@host`), другие схемы (`file:`, `gopher:`) не проходили и раньше.
3. **Нет CSP, нет запрета кэша у страницы, шрифты с Google Fonts и jsDelivr.**
   Сделано: JS и CSS вынесены в `web/app.js`, `web/app.css`; CSP: `script-src 'self'` (без `unsafe-inline`),
   `style-src 'self'` + `style-src-attr 'unsafe-inline'` (только атрибуты style у цветных точек графика — без них
   пришлось бы переписать отрисовку; скрипты и `<style>` встроить нельзя), `connect-src 'self'`, `frame-ancestors 'none'`,
   `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`; `Cache-Control: private, no-store`, `Referrer-Policy: no-referrer`,
   `X-Frame-Options: DENY`. Шрифты — свои в `web/fonts/` (лицензии в `web/fonts/README.md`). Страница входа — тоже без Google.
   После выхода — `Clear-Site-Data: "cache"`: «назад» не покажет панель.

### 🟢 Low

5. **Разбор параметров `^.*id=`** мог взять чужой параметр (`pcid=`). Внедрения не было (символы ограничены), но сделано точно:

6. **Не было журнала действий** (только входы) и уведомлений о перезагрузке/блокировке.

7. **Не было «выйти на всех устройствах»**, сессии с «Запомнить» живут 30 дней. Сделано: кнопка во вкладке «Роутер и сеть» (POST + Origin).
8. **Cookie сессии SameSite=Lax.** Сделано: `Strict` для `fsr_session`, `fsr_dev`, `fsr_2fa` (router.fspirat.online — тот же сайт, вход там не ломается).
9. **Имена из DHCP с управляющими символами** могли сломать JSON статуса (их задаёт само устройство). Сделано: `jesc()` их вырезает.
10. **Нет ограничения частоты API.** Сделано: nginx `limit_req` 5 запросов/с, пачка 30, сверх — 429 (`conf.d/fsr-limits.conf`).
11. **Опрос:** статус и данные опрашивались и во вкладке в фоне, медленный ответ мог копить запросы.
    Сделано: один запрос каждого вида за раз, в фоне — пауза, при возврате — сразу свежие данные.

### ℹ️ Informational (проверено, менять не нужно)

- **Сессии:** токен 256 бит (`random_bytes(32)`), в базе — только sha256; новый токен при каждом входе (фиксация невозможна);
  выход удаляет сессию на сервере — старая cookie сразу получает 401 (проверено тестом); IP-привязки нет (правильно: IP меняется).
- **Подбор:** 5 неверных паролей/кодов → вход с IP закрыт на 15 минут + fail2ban; код из Telegram — 5 попыток, 5 минут, хранится bcrypt.
- **XSS:** все строки с роутера, из подписки VPN (имена серверов) и из DHCP (имена устройств) идут через `esc()`;
  без экранирования — только числа, теперь явно приводятся к числу (`num()`).
- **Внедрение команд:** MAC, id, via, action — по белому списку символов; список сервисов проверяет Lua до записи в файл;
  в shell значения идут в кавычках; `encodeURIComponent` защитой не считался.
- **IDOR:** пользователь один; «усыпить» — только устройство, выбранное как ПК.
- **Выход по ссылке GET** оставлен (самое плохое — тебя разлогинят); «выйти везде» — только POST с Origin.

## Тесты (у себя, без production)

- **check.php** (PHP CLI, тестовая база): GET без токена — 204; POST с токеном и Origin — 204; со старым `X-FSR: 1` — 403;
  с чужим Origin — 403; без Origin — 403; токен от другой сессии — 403; без сессии — 401. Журнал пишет ACTION/DENY без токенов.
- **Выход:** после «Выйти» старая cookie — 401; после «выйти везде» — 401 у всех сессий.
- **nginx** (свой nginx + заглушка вместо PHP): проверка входа видит исходный метод POST, адрес, X-FSR и Origin;
  60 запросов подряд → 31 прошли, 29 получили 429. Новый сниппет из настоящего (без токена) — `nginx -t` ок, повторный запуск ничего не меняет.
- **CGI роутера** (песочница с заглушками): GET reboot/block → 405; POST block с верным MAC → 200; кривой MAC и `$(reboot)` → 400;
  неверный токен → 403; неизвестное действие → 400; внутренний адрес в списке → 400 `inner`; второй тест скорости → 409.
- **Список сервисов:** 13 проверок — внешние адреса проходят, все внутренние формы и чужие схемы — нет.
- **Страница** (Chromium, та же CSP, что будет на сервере): нарушений CSP — 0, ошибок JS — 0; ширины 320/375/390/768/1024/1440 —
  без горизонтальной прокрутки; окно подтверждения открывается, фокус на «Отмена», Esc закрывает без запроса;
  перезагрузка/блокировка/переименование уходят POST с токеном; ошибки 429/400/502 — понятным текстом;
  опрос: во вкладке сети скорость каждые 3 с, в фоне — 0 запросов, при возврате — сразу обновление.

## Выкладка (только после «Можешь выкладывать»)

Порядок важен: новая страница шлёт в `X-FSR` токен, а старый nginx пропускает только `X-FSR: 1` — поэтому **сервер первым**.

1. **Deploy server** с галочкой nginx — PHP, журнал, `fsr-limits.conf`, этап 4 nginx (копия конфига `*.bak-auth-…`,
   при ошибке `nginx -t` — откат сам). Старая страница продолжает работать: чтение и действия у неё — GET с `X-FSR: 1`
   (сервер пропускает GET по сессии, старый роутер их выполняет); не сработает только переименование устройства (POST без токена).
2. **Слить ветку в main** — страница выкладывается сама (~30 с). Новая страница шлёт действия POST с токеном —
   старый роутер POST тоже принимает, всё работает.
3. **Deploy router** — роутер начинает отклонять GET у действий (405). Перерыва нет.

Откат: revert слияния в main (страница), прошлый `Deploy router` из прошлого коммита, конфиг nginx — из `*.bak-auth-…`.
